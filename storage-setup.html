Store full-resolution images in the app

X-section supports two storage modes. The existing shared database accepts up to 8 MB of text and embedded optimized images per request. Cloud Storage stores original images and CAD files separately, so those files do not consume the request record's 8 MB capacity. Actual file capacity and cost depend on the Firebase project's quota and billing configuration.

  1. Open the existing project's Storage console. An authorized project administrator must create or enable the bucket if it is not already present. Review any billing prompt before enabling a paid service.
  2. Confirm that the bucket name matches storageBucket in firebase-config.js. The current configured bucket is lab-tracker-nvidia.firebasestorage.app.
  3. Merge the match /xsection/… block from firebase-storage.rules into the bucket's existing Storage rules and publish them. Preserve all existing rule blocks for other lab apps.
  4. Return to a request, reload the page, and add a picture. When Cloud Storage is available, the app saves the original and an optimized viewing copy and shows a Download original link. CAD/PDF attachments require Cloud Storage.

Until the bucket is available, image upload falls back to optimized images inside the existing shared database. The app reports this mode and refuses uploads that would exceed a request's capacity. It does not claim that an original was preserved when only an optimized copy was saved.

Current access model

The existing site uses anonymous Firebase sessions: anyone with the site address can access shared requests. The supplied file rules preserve that access model. This is not NVIDIA SSO or a private corporate deployment. Do not add confidential engineering data until the project owner has approved the hosting and access arrangement. A verified owner session is required to delete stored files.

Implementation follows Firebase's upload API and download URL API. No Storage rules or billing settings are changed by visiting this page.
